title: Escopos

Uma chave carrega um conjunto de escopos, e uma requisição fora desse conjunto é
recusada antes de chegar ao banco. Peça os menos que resolvem: uma chave é mais
fácil de entregar, e mais barata de perder, quando pode menos.

<ScopeTable />

Escopos se chamam `<recurso>.<read|write>`. O conjunto que uma chave pode ter é
uma constraint no banco, e não uma lista no código da aplicação, então um escopo
que não existe não pode ser guardado por caminho nenhum — inclusive um escrito
depois que esqueça de checar.

## Ausentes de propósito

<Callout>
**Sem escopo de comentários.** Comentário é a superfície por onde o abuso chega,
e uma API de publicar é uma API de abuso. Ela espera até existir um motivo.
</Callout>

- **Sem escopo de moderação.** Poder de moderador não se delega a uma chave.
- **Sem exclusão de conta.** Isso passa por segundo fator e confirmação
  digitada, e uma chave não é nenhum dos dois.
- **Nada alcança o dado privado de outra conta.** `social.read` devolve quem o
  dono segue, não o que essas pessoas têm.

## catalog.read é diferente

É o único escopo que não toca o dado de ninguém, e o que a maioria das
integrações realmente quer. Funciona numa chave que não tem mais nada — que é a
chave certa para um bot que só consulta jogos.
