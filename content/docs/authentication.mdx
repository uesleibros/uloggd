title: Autenticação
description: Um cabeçalho, um formato de token, e quatro recusas que respondem igual de propósito.
---

Toda requisição carrega sua chave num cabeçalho. Não existe outra entrada, e
nenhuma requisição é respondida sem ele.

```http
Authorization: Bearer ulg_live_...
```

## O token

Um token é `ulg_live_` seguido de 32 caracteres hexadecimais. O prefixo é o que
o torna reconhecível num log ou num texto colado, e é isso que torna possível
varrer por vazamentos.

Só um hash do token é guardado. Ninguém, nem nós, consegue ler uma chave depois
de criada: a coluna que guarda o hash não é concedida a nenhum papel que fale
com a API, então uma consulta que a alcance é recusada até para o próprio dono.

## O que uma recusa significa

<Callout type="warn">
Chave desconhecida, revogada, expirada ou malformada respondem todas o mesmo:
`401 invalid_key`. Elas não são distinguidas de propósito, para que um token não
possa ser sondado até se descobrir de que jeito ele está errado.
</Callout>

Uma chave viva que não tem a permissão responde `403 insufficient_scope`, e o
corpo nomeia o escopo que faltou:

```json
{
  "error": {
    "code": "insufficient_scope",
    "message": "This key does not hold library.write.",
    "scope": "library.write"
  }
}
```

## Até onde uma chave alcança

A requisição roda como a conta dona da chave. Uma chave com `lists.write` numa
conta que não pode escrever em certa lista privada continua não podendo,
porque quem recusa é a regra da própria lista, não o escopo.

Um escopo é um teto. Ele estreita o que a chave pode tentar; nunca amplia o que
o dono dela pode fazer.

## Cuidando de uma chave

- Trate como senha, porque é uma que dispensa a senha.
- Dê uma chave para cada integração. Revogar uma não custa nada às outras.
- Revogue em **Configurações → Desenvolvedor** assim que uma chave escapar. A
  revogação vale já na requisição seguinte.
