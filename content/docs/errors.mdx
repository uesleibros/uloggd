`code` é estável e existe para ser comparado. `message` é para quem lê um log e
**não** é contrato: pode ser reescrito a qualquer momento.

```json
{
  "error": {
    "code": "insufficient_scope",
    "message": "This key does not hold library.write.",
    "scope": "library.write"
  }
}
```

## De onde vem uma recusa

A maioria das recusas é do banco, não do handler. Uma constraint, uma coluna não
nula, um gatilho de limite ou uma política de linha levanta o erro, e esse erro
é traduzido para o formato acima.

Só as recusas levantadas de propósito levam a mensagem para fora. Qualquer outra
responde `internal` sem dizer mais nada, porque mensagem de erro imprevista é
descrição do schema.

<Callout type="warn">
`404 not_found` cobre dois casos de propósito: o recurso não existe, e o recurso
existe mas o dono da chave não pode vê-lo. Distinguir os dois seria um jeito de
perguntar se a lista privada de alguém existe.
</Callout>
